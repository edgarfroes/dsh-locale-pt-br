# Contributing translations

[Português](CONTRIBUTING.md) | English

Thanks for helping! You don't need to be a programmer: translations are plain
JSON files. All you need is [Node.js 22](https://nodejs.org/) and Git.

## 1. Set up

1. Fork [edgarfroes/dsh-locale-pt-br](https://github.com/edgarfroes/dsh-locale-pt-br) on GitHub.
2. Clone your fork and create a branch:

   ```bash
   git clone https://github.com/<your-user>/dsh-locale-pt-br.git
   cd dsh-locale-pt-br
   git switch -c translate-<topic>
   ```

There are no dependencies to install.

## 2. Where the strings live

| File | What it holds |
| --- | --- |
| `data/en.json` | The English source of every string, by namespace. **Don't edit by hand**: it is generated from dsh. |
| `dictionaries/<namespace>.json` | The translation of each string. **This is what you edit.** |
| `GLOSSARY.md` | Terms already chosen (sessão, workspace, predefinição…). |
| `lib/client.js` | Generated by `npm run build`. **Don't edit by hand.** |

Each namespace is one part of the UI: `chat`, `workspace`, `settings.models`… To find a
string you saw on screen, search its English text in `data/en.json`:

```bash
grep -n "New Session" data/en.json
```

The key you find (for example `session.new` in namespace `sidebar`) is the same one in
`dictionaries/sidebar.json`.

## 3. Translate

Open `dictionaries/<namespace>.json` and change only the value, never the key:

```json
{
  "session.new": "Nova sessão"
}
```

Rules:

- **Placeholders**: keep every `{name}` exactly as in the English, wherever it fits the
  sentence. `"{count} files"` → `"{count} arquivos"`. `npm run check` rejects
  placeholders that differ.
- **Plurals**: keys ending in `.one` and `.other` are singular and plural.
- **Tone**: Brazilian Portuguese, direct, addressing the person as "você". Buttons and
  actions in the infinitive ("Salvar", "Abrir barra lateral"); messages as short sentences.
- **Capitals**: first word only ("Nova sessão", not "Nova Sessão").
- **Don't translate**: product and app names (VS Code, GitHub), commands (`/plan`,
  `compact`), file and protocol names (cordis.patch.yml, OpenAI Responses), and
  technical values such as the `sidebarExcel` key `language` (`en`).
- **Terms**: follow `GLOSSARY.md`. To change a term, change it in every file in the
  same PR and update the glossary.
- Empty English strings (`""`) need no translation.

## 4. Check

```bash
npm run check   # every string translated, with the same {placeholders}
npm run build   # regenerate lib/client.js
npm test        # tests
```

All three must pass. Commit the regenerated `lib/client.js` too.

To see it on screen: install your branch into dsh (`npm pack`, then
`dsh plugin --profile web add <path>/dsh-locale-pt-br-<version>.tgz`) and pick
Português (Brasil) in Settings → General → Language.

## 5. Open the PR

```bash
git add dictionaries lib/client.js GLOSSARY.md
git commit -m "pt-BR: <what changed>"
git push -u origin HEAD
```

Open the pull request on GitHub. Say what changed and why; attach a screenshot if you
can. CI runs `check`, `build --verify` and the tests.

## When a new dsh version comes out

Maintainers (or anyone who wants to get ahead):

```bash
npm install --no-save @deepseek-ai/dsh@<version>
npm run extract -- node_modules data/en.json
npm run check   # lists what's missing and what dsh dropped (stale)
```

Translate the `missing` keys, delete the `stale` ones, run `build` and `test`, and open
the PR with the dsh version in the title. Update the tested version in the README.

## Translating into another language

This repository is pt-BR only, but it works as a template for a pack in any language:

1. Create a new repository from a copy of this one (for example `dsh-locale-<id>`).
2. In `scripts/build.mjs`, change `LANGUAGE` (`id` as a BCP 47 tag such as `it` or
   `fr-CA`; `label` as the language's own name; `fallback: 'en'`) and `PLUGIN_ID`.
3. In `package.json`, change `name`, `description`, `dsh.market.description`,
   `keywords` and the repository URLs. In `cordis.patch.yml`, change the `id`.
4. Replace every `dictionaries/<namespace>.json` with your translations (start by
   copying the English values from `data/en.json`, then translate).
5. Adjust the tests that mention `pt-BR`/`Português (Brasil)` in `test/pack.test.mjs`,
   the READMEs and the LICENSE (keep whatever credits still apply).
6. `npm run check && npm run build && npm test`, and publish the same way (tag `v*` →
   release with the `.tgz`).
